On your second question, I have to answer it differently from my first attempt,
because looking into what the correct answer even is changed the picture.

What it asks for is its AppUserModelID, through both routes that exist: the window
property store's PKEY_AppUserModel_ID, and GetCurrentApplicationUserModelId. What I
had not checked is what a process in this state is entitled to get back.

Microsoft's AppUserModelIDs documentation says an explicit AppUserModelID is optional,
that the system otherwise assigns one through heuristics, and that "Applications cannot
retrieve a system-assigned AppUserModelID". This application never declares one: it
never calls SetCurrentProcessExplicitAppUserModelID, and it never calls SetValue on the
store -- in that trace GetValue is the only store method it uses. So on Windows it is
asking for something it is not entitled to retrieve, and a failure is the correct
outcome for it.

Wine's side is

    LONG WINAPI GetCurrentApplicationUserModelId( UINT32 *length, WCHAR *id )
    {
        FIXME( "(%p %p): stub\n", length, id );
        return APPMODEL_ERROR_NO_APPLICATION;
    }

which is what produces the log line above, and is consistent with the documentation for
this case.

So the honest answer to "what does it need from it" may be: nothing -- which is also
why the application just carries on. I had meant to follow up by proposing that the
AUMID path be implemented; on the evidence above I do not think that holds for an
application that never declares an ID, so I am not proposing it.

What I cannot rule out is the window property store route. On Windows a window without
an explicit AppUserModelID inherits the AppUserModelID of the process, and the process
can have one from its shortcut, so GetValue(PKEY_AppUserModel_ID) might return something
where Wine returns E_NOTIMPL. I have no Windows machine to check that on and I am not
going to guess.

Which leaves the original question of this report: whether initialising the out
parameter is worth doing on its own. It is a much smaller claim than the one I opened
with, and I would understand if the answer is that it is not.
